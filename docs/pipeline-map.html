SCRATCH-E2E

A single-cell RNA-seq pipeline that runs as one linear backbone, splits the cohort into malignant and non-malignant compartments, then follows each compartment down its own arm. Every stage is independently enterable, so you can start from FASTQs, from count matrices, or from any intermediate Seurat object.

01The whole pipeline

Edges are labelled with what actually moves between stages — the object or the calls, not just "next". The split at STRATIFY is the pivot: everything above it is one cohort, everything below is two.

05Entering the pipeline

--from and --to select a contiguous span of the backbone; --only runs named stages alone. Any stage entered mid-chain takes its input object from --input_seurat_object.

From raw counts, through annotation

The most common entry. Runs QC → CLUSTER → ANNOTATION on CellRanger output.

nextflow run SCRATCH-E2E -profile docker,local \
  --from qc --to annotation \
  --input_gex_matrices_path 'TESTDATA/cellranger/*/outs/*' \
  --input_exp_table TESTDATA/sample_metadata.csv \
  --input_reference_object TESTDATA/ov_meta_reconstructed.rds \
  --project_name hgsoc_raw --outdir results/annotation

CNV calling on an annotated object

Hand it the scType aggregate object: celltype_col defaults to sctype, and the reference lineages inferCNV measures against are named in that vocabulary. The Azimuth object matches only one of the six.

nextflow run SCRATCH-E2E -profile docker,local \
  --from cnv --to stratify \
  --input_seurat_object .../hgsoc_raw_sctype_agg_annotation_object.RDS \
  --project_name hgsoc_raw \
  --outdir results/cnv

Allele-aware calling with Numbat

Needs a position-sorted genome BAM per sample. The sample key is the directory two levels above the BAM, and must match the object's sample column.

nextflow run SCRATCH-E2E -profile docker,local \
  --from cnv --to cnv --run_numbat true \
  --input_seurat_object .../hgsoc_raw_sctype_agg_annotation_object.RDS \
  --input_bam_path '.../CELLRANGER_COUNT/*/outs/possorted_genome_bam.bam' \
  --project_name hgsoc_raw --outdir results/numbat

One arm only, from a compartment object

--input_tumor_object and --input_nonmalignant_object enter an arm directly, without re-running the split.

nextflow run SCRATCH-E2E -profile docker,local \
  --from batchcorrect \
  --input_nonmalignant_object .../hgsoc_nonmalignant_object.RDS \
  --celltype_col sctype --sample_col sample_id --condition_col condition \
  --project_name hgsoc_stromal --outdir results/stromal

06Things the diagram can't show

The split is only as good as the callers

STRATIFY pools whichever callers ran. With one caller there is no cross-check — the compartment assignment rests on a single method and a threshold.

Annotators disagree

The three annotators use different label vocabularies at different resolutions. Downstream stages key on sctype, so that choice propagates into composition, abundance and communication results.

Stub proves wiring, not behaviour

The 56-task stub suite exercises the DAG without invoking a single notebook. A green stub says the graph connects; it says nothing about whether a stage produces correct output.
